## Goal

Extend the wiki schema with edge weights, two new relation types (`derived_from`, `part_of`), two new page types (`concept`, `hypothesis`), and an atomic node size cap — bringing the retrieval model closer to an AI-first design that scales to 1,000 pages.

---

## Context

A review of AI-first PKM design patterns (five pillars: atomic nodes, typed nodes, typed edges with weights, trust metadata, namespaces) revealed gaps in our current schema:

1. **No edge weights** — agents treating `related_to` the same as `contradicts` make poor traversal decisions.
2. **Missing edge types** — no way to express provenance (`derived_from`) or composition (`part_of`).
3. **Missing page types** — `concept` and `hypothesis` cover a gap between glossary entries and full module pages.
4. **No size cap** — pages can grow unboundedly, forcing full-load instead of targeted retrieval.

Trust metadata (Pillar 4) was already implemented in the previous session.

---

## Scope

**In scope:**
- Add weights column to the relation type vocabulary in CLAUDE.md and metadata-model.md
- Add `derived_from` and `part_of` edge types
- Add `concept` and `hypothesis` to the `type:` vocabulary
- Add `derived_from: []` and `part_of: []` to the frontmatter template's `relations:` block
- Add atomic node size cap (50–300 lines) to CONVENTIONS.md with a validator warning
- Sync CLAUDE.md mirrors: AGENTS.md, .github/copilot-instructions.md
- Update validator to allow new edge types and emit size warnings

**Out of scope:**
- Namespaces/visibility (Pillar 5) — not enough detail from source material
- Other new node types (playbook, task, event, etc.) — don't fit a software wiki use case
- Splitting any existing pages to meet the size cap — that's a separate lint/cleanup task

## Technical Approach

All changes are additive. No existing pages break because:
- New edge types are added to the validator whitelist (old pages don't use them, so no failures)
- New page types are just new valid values for the `type:` field (no validator enforcement of a strict enum)
- The size cap is a `warn` not a `fail` in the validator (no retroactive failures)
- Frontmatter template additions are optional fields in existing pages

The three CLAUDE.md mirrors must stay in sync — update CLAUDE.md first, then copy verbatim to AGENTS.md and .github/copilot-instructions.md (preserving each file's 2-line header).

## Notes

The 9 edge types from the source material were reduced to 7 (dropping `preceded_by`, `followed_by`, `authored_by`, `tagged_with`) because:
- `authored_by` / `tagged_with` are already covered by `owner` field and `tags:` frontmatter
- `preceded_by` / `followed_by` are temporal ordering edges with little relevance in a software wiki where pages aren't sequenced narratives
